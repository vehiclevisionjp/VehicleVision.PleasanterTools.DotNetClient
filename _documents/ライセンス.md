### NuGet のメタデータ

`PackageLicenseExpression` は `LicenseRef-*` を扱えず、利用者の限定も表せない。
そのため式は使わず、`PackageLicenseFile` で `LICENSING.md` を指す（`Directory.Build.props`）。
パッケージの直下へ `LICENSING.md`・`LICENSE-COMMERCIAL.md`・`LICENSE`・`COPYING`・`LICENSE-AGPL`・`NOTICE` を同梱する（`src/.../*.csproj`）。

## 守ること

1. **Pleasanter 本体（AGPL v3）のコードを取り込まない。** コピー・流用・リンク・プロジェクト参照のいずれも不可。
   本体の著作権は自社に無く、AGPL のコードを含めると LGPL と商用ライセンスで提供できなくなる。
   `_reference/` は事実確認のための参照専用で、`scripts/reference-isolation-check.sh` が混ざりを検査する。
   **コードを流用していないことの開発者への確認は済んでいない**ので、断定しない
2. **依存は寛容ライセンス（MIT / BSD 系 / Apache-2.0）に限る。** GPL・AGPL 等のコピーレフトの依存を入れない（B・C の提供と、LGPL の差し替え可能性が崩れる）。
   追加時に一次情報で確認し、`NOTICE` へ追記する
3. **外部の貢献は、取り込む前に CLA で再許諾を受ける。**
   LGPL・AGPL・商用ライセンスのいずれでも提供するため。著作権の譲渡ではなく、貢献者の著作権は貢献者に残る。
   手続きは [貢献のしかた](../CONTRIBUTING.md)、草案は [CLA](../CLA.md) を参照する。
   **正式な同意を受ける前に法務確認が必要**

## Core との関係

本ライブラリは VehicleVision.PleasanterTools.Core に依存せず、Core のライセンスとは独立している。
今後、共有する処理は Core に置く方針のため（先回りの注記）、**依存が生じた時点でライセンスの整合を見直す**。
Core 側の商用ライセンスとの関係と、必要なら Core 側での例外許諾を確認する。
今の時点で、Core のライセンスを上書きする仕組みは設けていない。

## 後からライセンスを変えるとき

公開した版は、その版の利用者に、そのときのライセンスで許諾済み。
以後の版を別のライセンスにする場合は、**対象コードの権利と必要な再許諾を受けていること**を確認してから行う。
CLA を置くこと自体はライセンスの変更ではなく、既存の全コードに対する許諾が揃っていることの証明にもならない。
