# リリース手順

NuGet パッケージ `VehicleVision.PleasanterTools.DotNetClient` を **nuget.org** へ公開する。

## 版

版の単一情報源は `Directory.Build.props` の `VersionPrefix`（開発中の版の目安）。公開する版は**タグ**（`vX.Y.Z`）で決まり、`release.yml` が `-p:Version` へ渡す。
セマンティックバージョニングに従い、1.0.0 未満は互換を保証しない。`vX.Y.Z-preview.N` のようにハイフン付きの版はプレリリースになる。

## 一気通貫で出す（推奨）

「リリース実行（Release Run）」ワークフローが、版の引き上げ PR、`develop` → `master` の PR、
マージ、タグの push までを 1 回で通します。タグの push を受けて `release.yml` が nuget.org へ公開します。
**公開した版は取り消せません**（nuget.org では削除できず、非推奨にできるだけ）。タグも付け直せません。
そのため、既定は dry-run で、実際に出すときは `acknowledge` の明示を要求します。

1. `develop` の CI が緑であることと、下の「公開前の確認」を済ませる。
2. まず dry-run を実行する（既定が `dry_run=true`）。出る版と前提を確認する。

   ```bash
   gh workflow run release-run.yml --ref develop -f bump=patch
   ```

3. 問題なければ、実際に出す。`acknowledge` は、機械で確かめられない確認（破壊的変更の版、
   依存のライセンス）を済ませた表明です。

   ```bash
   gh workflow run release-run.yml --ref develop -f bump=patch -f dry_run=false -f acknowledge=true
   ```

- 採番の起点は既存の最新 `v*` タグです（`scripts/release-next-version.sh`）。
  タグがまだ無い初回だけは、`VersionPrefix` をそのまま出す版にします（`bump` は無視）。
- プレリリース（`vX.Y.Z-preview.N`）は、このワークフローでは出しません。手で出します（下の「手で出すとき」）。
- 実際に出す実行は、公開の準備（下の「公開の準備（初回）」）が済んでいないと、前提の確認で止まります。
  **準備が無いままタグを作ると、公開に失敗してタグだけが残る**ためです。
- `my-repo-automation-bot`（GitHub App）のトークンで動きます。
  Repository Variable `MY_REPO_AUTOMATION_BOT_CLIENT_ID` と Secret `MY_REPO_AUTOMATION_BOT_PRIVATE_KEY` が要ります。
- `develop` へのマージ後に落ちると、版だけ上がってタグが無い状態になります。再実行すると、
  既にある PR とブランチは作り直さず引き継ぎます。

## 手で出すとき

1. 版を上げる必要があれば、`develop` で `VersionPrefix` を上げる
2. `develop` から `master` へ PR を出し、**マージコミット**（スカッシュしない）でマージする
3. `master` の先頭に、注釈付きタグ `vX.Y.Z` を付けて push する
4. タグを契機に `release.yml` が、ビルド・テスト・pack を行い、nuget.org へ公開する
5. nuget.org の一覧に反映されるまで数分かかる。確認は `dotnet restore --no-cache`

## 公開の準備（初回）

nuget.org への公開は **Trusted Publishing**（API キーを持たない）。Core リポジトリと同じ仕組みで、次を整える。

- 組織の変数 `NUGET_ORG_USER`（公開用の共有アカウントの nuget.org プロフィール名）を、このリポジトリへ共有する
- nuget.org の Trusted Publishing のポリシーに、このリポジトリと `release.yml` を登録する
- `VehicleVision` の ID プレフィックスは予約済み（公開用の共有アカウント）

## 公開前の確認

- `LICENSING.md`・`LICENSE`（LGPL）・`LICENSE-AGPL`・`LICENSE-COMMERCIAL.md`・`COPYING`・`NOTICE` が現状と合っている（3 層: LGPL-3.0-or-later OR AGPL-3.0-or-later OR LicenseRef-PMC-Commercial）
- パッケージに設定ファイル・秘密・参照ソース・Git メタデータが入っていない。
  既定先 `_reference/Implem.Pleasanter/` だけでなく、`PLEASANTER_REFERENCE_DIR` の共有先も含めない。
  `bash scripts/reference-isolation-check.sh` と `dotnet pack --no-build -c Release -o artifacts` で検証し、
  生成した `.nupkg` の内容を確認する。公開方式は従来どおり NuGet の Trusted Publishing
